# Suzu_Ai architecture

```
┌─────────────────────────┐         HTTPS / WSS         ┌──────────────────────────────┐
│  Android client (APK)   │ <─────────────────────────> │  FastAPI server (8 GB box)   │
│                         │                             │                              │
│  - Compose UI           │     POST /v1/chat (SSE)     │  - Agent loop (max_iter=100) │
│  - Sidebar (new/hist/   │     POST /v1/chats          │  - Multi-provider with       │
│    settings)            │     POST /v1/chats/{id}     │    auto-fallback (Anthropic, │
│  - Hacker terminal      │     POST /v1/files          │    OpenAI-compat, OpenRouter)│
│    theme                │     POST /v1/tools/...      │  - Tools:                    │
│  - Room DB (history)    │                             │      shell, read, write,     │
│  - Multi-provider       │                             │      edit, grep, ls,         │
│    profiles             │                             │      apk_decompile,          │
│  - Defensive JSON       │                             │      apk_recompile, apk_sign │
│    parsing              │                             │  - Per-session workspace     │
│                         │                             │    sandbox                   │
└─────────────────────────┘                             └──────────────────────────────┘
```

## Server

- **Framework**: FastAPI + Uvicorn.
- **Storage**: SQLite (`sessions.db`) for chat persistence; filesystem (`workspace/{session_id}/`)
  for the agent's working directory.
- **Auth**: shared bearer token (`SUZU_TOKEN`) — generated by `install.sh` and pasted into the app.
- **Streaming**: Server-Sent Events on `POST /v1/chat`. Each event is one JSON object on a single
  line, prefixed with `data: `. Event types: `delta`, `tool_call`, `tool_result`, `done`, `error`.
- **Providers** (`providers.py`): adapter for Anthropic-native + OpenAI-compatible (covers
  OpenAI, OpenRouter, AfiqStoreAPI, Together, Groq, etc.). Each profile has an ordered list of
  API keys; when the active key hits 401/402/429 the loop transparently advances to the next key
  and retries the current turn. Profile metadata also includes base URL and model name.
- **Agent loop** (`agent.py`): Anthropic-style "tool use" loop. The model emits `tool_use` blocks,
  the server executes them, returns `tool_result`, repeats. Iteration cap defaults to 100 and is
  configurable per-request (so the previous build's `max_iterations=12` crash never returns).
- **Tools** (`tools/`): each tool has a JSON schema, an executor, and a streaming preview hook so
  the phone shows progress live.

## Android client

- **Module layout**: single-app Gradle module under `android/app/`.
- **DI**: simple manual singletons (no Hilt — keeps APK small).
- **Network**: OkHttp + kotlinx-serialization. SSE consumed line-by-line; every parse is wrapped
  in defensive `runCatching` + `JsonElement.jsonObjectOrNull` checks so a stray `null` from a
  provider doesn't crash the chat.
- **Persistence**: Room DB stores chats (id, title, created/updated) and messages (id, chat_id,
  role, content, tool calls, timestamps). DataStore stores provider profiles and server config.
- **Theme**: one hacker terminal palette — black background, cyan/green accents, JetBrains Mono.
  Light theme intentionally dropped for Lite.

## Lite scope

What's *out* (to keep the APK small and the diff manageable):

- Multiple theme switcher (only hacker terminal).
- File browser tab (you can still ask the agent to `ls` / `cat`).
- Voice input.
- Push notifications.
- E2E encryption (the bearer token over HTTPS is your security boundary).

What's *in*:

- Full Devin-style agent loop on the server.
- All the APK-engineering tools (decompile/recompile/sign).
- Multi-provider with auto-fallback.
- Chat history (rename, delete, resume).
- Copy on every message + code block + tool output.
- Live streaming with tool-call previews.

## Why "Lite"

`Suzu_Ai` lite means **the phone is light, the brain is heavy**. The APK is small (~5-8 MB
target after R8) and only contains the UI + settings + streaming client. Everything the agent
actually does — shell commands, file edits, APK reverse engineering — happens on your server.
